# Exam Engine client — `lib/features/shared/exam_engine/`

This file is loaded when working in this folder; the app-wide rules are in the root `CLAUDE.md`. The RAG client and the app assistant: `lib/features/shared/rag/CLAUDE.md`.

**Exam Engine and RAG clients (`lib/features/shared/exam_engine/`, `lib/features/shared/rag/`)** — separate backend services (`../back/exam_engine`, `../back/rag_service`) reached through the same `ApiClient` under `/api/v1/exam/…` and `/api/v1/rag/…`. Engine calls go through `engineCall` → `EngineResult`; `unavailable` (bare 404 / 405) means the engine is not routed and the legacy exam flow stays in charge (`engine_exams_section.dart` shows nothing then). Server codes become text via `examCodeText` (exam files) and the RAG files' own maps. Pure, unit-tested parts: `Paper`, `ServerClock`, `AutosaveQueue` (pending answers, `restore()` after an app kill), `EventBuffer`, `PolicyAction` in `exam_taking.dart`; `RagCitation`, `RagAnswer`, `answerRuns` in `rag_chat.dart`. Tests: `test/org/exam_*_test.dart`, `test/org/rag_*_test.dart`. User-facing behaviour of these features is described in `docs/NEW_FEATURES_GUIDE.md`. The exam files follow one pattern: a pure `exam_x.dart` (models, API, code → text, unit-tested) next to an `exam_x_screen.dart` / `_sheet.dart` whose presentational widgets take plain values so the layout harness can pump them. The pieces built on top of the full editor (`exam_authoring.dart`):
- `exam_quick.dart`: the quick exam (Online or Offline first, then questions or one uploaded file, everything else a default under "Advanced"); it builds the same engine objects as the editor (`QuickExam`, `createQuickExam`), and is where exam timetables (`settings.schedule_slot_id`) and "My exams" create exams from.
- `exam_generate.dart`: "Generate the questions for me" — `POST /api/v1/rag/exam-drafts` (202, then polled; 409 `no_course_documents`) lands RAG-written questions in the quick exam as an editable draft.
- `exam_paper.dart` + `exam_paper_pdf.dart` / `exam_paper_docx.dart`: the printable paper (Classic / Modern / Minimal / Auto, or the creator's own Word template with `{{placeholders}}`), paper or answer key, built from the manager's `GET /exams/{id}`. `package:pdf` needs the bundled IBM Plex Sans Arabic (presentation forms that Cairo / Tajawal lack).
- `exam_paper_flow.dart`, `exam_scan_review.dart`: paper exams with scanned answer sheets (bulk scan upload, mapping file, offline marks import, OCR correction, unmatched queue).
- `exam_integrity.dart` (+ `_web` / `_stub` conditional imports): integrity signals the platform can observe (tab switch, full-screen exit, copy / paste, app backgrounded), event kinds only, never content.
- `offline/`: offline sittings — the exam package is the server's AES-GCM ciphertext, the key is released only inside the exam window or passed from a nearby phone over the attendance relay link (`offline_exam_relay.dart`: every message X25519 + AES-GCM encrypted, the key only as per-student wraps), answers are sealed bundles and only the server's HMAC receipt counts as submitted. `offline_exam_core.dart` is the pure part; `offline_exam_service.dart` is the phone's encrypted store and sync; `_screen` (student) and `_teacher` (hand out / collect / bulk upload / auto-grade) are the UIs. Students sit offline on phones only. Server contract: `../back/exam_engine/services/offline.py`.
- `PasscodeSheet` (`lib/features/shared/passcode/passcode_screen.dart`) is the reusable PIN sheet (exam passcodes, private courses); the caller supplies `verify`.
