# Exam Engine client — `lib/features/shared/exam_engine/`

This file is loaded when working in this folder; the app-wide rules are in the root `CLAUDE.md`. The RAG client and the app assistant: `lib/features/shared/rag/CLAUDE.md`.

**Exam Engine and RAG clients (`lib/features/shared/exam_engine/`, `lib/features/shared/rag/`)** — separate backend services (`../back/exam_engine`, `../back/rag_service`) reached through the same `ApiClient` under `/api/v1/exam/…` and `/api/v1/rag/…`. Engine calls go through `engineCall` → `EngineResult`; `unavailable` (bare 404 / 405) means the engine is not routed and the legacy exam flow stays in charge (`engine_exams_section.dart` shows nothing then). Server codes become text via `examCodeText` (exam files) and the RAG files' own maps. Pure, unit-tested parts: `Paper`, `ServerClock`, `AutosaveQueue` (pending answers, `restore()` after an app kill), `EventBuffer`, `PolicyAction` in `exam_taking.dart`; `RagCitation`, `RagAnswer`, `answerRuns` in `rag_chat.dart`. Tests: `test/org/exam_*_test.dart`, `test/org/rag_*_test.dart`. User-facing behaviour of these features is described in `docs/NEW_FEATURES_GUIDE.md`. The exam files follow one pattern: a pure `exam_x.dart` (models, API, code → text, unit-tested) next to an `exam_x_screen.dart` / `_sheet.dart` whose presentational widgets take plain values so the layout harness can pump them. The pieces built on top of the full editor (`exam_authoring.dart`):
- `exam_quick.dart`: the quick exam (Online or Offline first, then questions or one uploaded file, everything else a default under "Advanced"); it builds the same engine objects as the editor (`QuickExam`, `createQuickExam`), and is where exam timetables (`settings.schedule_slot_id`) and "My exams" create exams from.
- `exam_generate.dart`: "Generate the questions for me" — `POST /api/v1/rag/exam-drafts` (202, then polled; 409 `no_course_documents`) lands RAG-written questions in the quick exam as an editable draft.
- `exam_paper.dart` + `exam_paper_pdf.dart` / `exam_paper_docx.dart`: the printable paper (Classic / Modern / Minimal / Auto, or the creator's own Word template with `{{placeholders}}`), paper or answer key, built from the manager's `GET /exams/{id}`. `package:pdf` needs the bundled IBM Plex Sans Arabic (presentation forms that Cairo / Tajawal lack).
- `exam_forms_import.dart`: import a draft's questions from Google Forms (D-291). The Google Picker runs in a server page in the system browser, because it cannot run in a webview; the core reads the form, the engine's `POST /exams/{id}/questions/import-rows` applies the Excel import's checks. Needs `GOOGLE_PICKER_API_KEY` on the server; kill switch `exam.google_forms_import`, which the server also adds to the disable list while that key is unset (`derived_off`), so the button is hidden rather than answering 503.
- `exam_paper_flow.dart`, `exam_scan_review.dart`: paper exams with scanned answer sheets (bulk scan upload, mapping file, offline marks import, OCR correction, unmatched queue).
- `paper/`: paper exams with bubble sheets (D-150 – D-160 in `../back/docs/DECISIONS.md`; end to end in `docs/guides/paper-exams-omr.md`). Same pattern: a pure, unit-tested file (`exam_setup.dart`, `scan/omr_scan.dart`, `templates/omr_templates.dart`, `review/omr_review.dart`: models, request bodies, server codes in words, the calls) next to screens whose bodies are plain-value widgets (`SetupFrame`, `omr_scan_widgets.dart`, `omr_review_parts.dart`, `omr_results_parts.dart`, `Learn*Body`) the layout harness pumps. `exam_setup_wizard.dart` is "Paper exam setup" (Students → Type → Paper → Bubble sheet → Models; every step PUTs only its own keys to `…/setup`), opened from the editor's app bar and after an Offline quick exam with a course; `scan/` is the bubble part of `ExamScansScreen` (`OmrScanSection`: print, camera, upload, Review, Results; `OmrRoutes` points at the review / results pages so a test can swap them) and the camera behind `OmrCamera` (flutter_webrtc on phones, `package:web` getUserMedia on the web — no camera package); `paper_exam_entry.dart` is the "Paper exam" card every paper exam shows on its own screens (results, editor, the quick builder's end) — the permanent way into print / scan / review / results; `scan/omr_audience_picker.dart` picks students by name for named sheets (`GET …/omr/students`); `templates/` is the super admin's library (services hub tile "Bubble sheet types") and the learning flow a teacher reaches through "Upload a custom layout"; `review/` is the queue and the results. Nothing polls on a bare timer: the wizard follows `exam_identifiers`, scan progress / review / results follow `job_updated {kind: omr_scan, exam_id}`, learning follows `job_updated {kind: omr_template, id}`, all through `EventOrPoll` with a slow poll as the fallback. Never decide a grade in the app: what is final vs review is the engine's answer, the app only shows it. Kill switches `exam.omr` (every bubble part) and `exam.identifiers` (the wizard's first step + the student dialog in `lib/features/shared/identity/`).
- `paper/bubble/`: the premium bubble-sheet flow (D-340 – D-343, table in `docs/guides/paper-exams-omr.md`): `bubble_flow.dart` (pure), `bubble_widgets.dart` + `bubble_sheet_view.dart` (plain values), `BubbleHomeScreen` · `BubbleImportScreen` (teach any sheet) · `BubbleRunScreen` · `BubbleKeyScreen` · the Data Lab sheet. A run is an exam (`settings.bubble_run`), so upload / progress / review / results are `scan/` and `review/`. Kill switches `exam.bubble`, `exam.bubble.teach`, `exam.bubble.key_sheet`, `exam.bubble.datalab`. Tests: `test/org/bubble_flow_test.dart` (fixtures `test/fixtures/payloads/bubble/`, recorded by the backend e2e), `test/ui/bubble_layout_test.dart`.
- `exam_integrity.dart` (+ `_web` / `_stub` conditional imports): integrity signals the platform can observe (tab switch, full-screen exit, copy / paste, app backgrounded), event kinds only, never content.
- `offline/`: offline sittings — the exam package is the server's AES-GCM ciphertext, the key is released only inside the exam window or passed from a nearby phone over the attendance relay link (`offline_exam_relay.dart`: every message X25519 + AES-GCM encrypted, the key only as per-student wraps), answers are sealed bundles and only the server's HMAC receipt counts as submitted. `offline_exam_core.dart` is the pure part; `offline_exam_service.dart` is the phone's encrypted store and sync; `_screen` (student) and `_teacher` (hand out / collect / bulk upload / auto-grade) are the UIs. Students sit offline on phones only. Server contract: `../back/exam_engine/services/offline.py`.
- `PasscodeSheet` (`lib/features/shared/passcode/passcode_screen.dart`) is the reusable PIN sheet (exam passcodes, private courses); the caller supplies `verify`.
- **Grading, grade review, publishing (D-240 – D-249, contract `../back/docs/grading/CONTRACT.md`).** `exam_grading.dart` (+ `_widgets`) = publish / unpublish (409 `review_pending` | `review_items_open` → `PublishBlockedSheet`, "publish the reviewed ones" = `graded_only`), `results_view`, cancel a question (void / restore), analytics `option_stats` (the old `options` map stays for installed apps); `exam_grade_log_screen.dart` = the grade log; `parent_grade_visibility.dart` = the super admin / org admin parent-visibility sheet; `exam_notice.dart` routes the `exam_notice` live event / push by `kind` (appeals, results, `batch_done` → `paper/scan/omr_batch_notice.dart`, `mark_session_done` → the session). `marks/` = teachers' own paper sheets: `templates/` registers a cover / mark sheet / answer table (photograph a blank → proposed boxes → drag / resize / draw → field types → sum rule → test on one filled sheet; `openMarkTemplates(context, orgId:, pick:)`), `review/` is grade review by camera and mark import (start → continuous capture, the phone only captures → match / mismatch / unreadable → a person applies each correction; `openGradeReview`, `openMarkSessionFromNotice`), `marks_links.dart` joins them for the Data Lab action (kill switch `exam.grade_review`) and the exam review screen's menu. Tests: `test/org/{exam_publish_flow,exam_question_void,exam_grade_log,parent_grade_visibility,mark_templates,grade_review,omr_scan_issues}_test.dart` + their `test/ui/*_layout_test.dart`.
- **All exams (D-300).** `exam_all.dart` (pure: `AllExam`, `AllExamsFilter`, `filterAllExams`, `allExamCounts`, `loadAllExams`, `newExamPlaces`) + `exam_all_screen.dart` (`AllExamsScreen`, plain-value `AllExamsBody` / `AllExamCard` / `AllExamTable`): every exam the person manages in ONE `GET /exams/mine?org_ids=&course_ids=` (falls back to the per-space lists on an older engine), opened with `deferredAllExams()`; kill switch `exam.all_exams`. The quick builder's chooser offers "Import from Google Forms" (`QuickStart.forms`, `GoogleFormsImportSheet(createExam:)` makes the draft after the pick). Test: `test/org/exam_all_test.dart`.

- **Generation as a background job, speed, the switches (D-301).** The wizard's Generate step follows the job (`GenProgressView`: status, N / M ready, time left, the questions as they arrive; Add the ready now · Stop · Keep it running · Try again) and never times out into "try later"; `ExamGenEntry` resumes the course's running or untaken job (`GET /rag/exam-gen?course_id=`, `genResumableOf`). Language step: Fast / Best quality (`GenSpeed`); Sources step: write from a topic (`GenTopicCard`). The builder sends its own prompts as `avoid_prompts`. Kill switches `exam.auto_create` (the Generate card / chooser tile) and `exam.auto_correct` (bubble scan section, scan upload, camera grade review, offline auto-grade: `exam_features.dart`, `examAutoCorrectAllowed`); the services answer 403 `feature_disabled`. Tests: `test/org/exam_generate_d301_test.dart`.

- **Exam Hub (`hub/`, D-356, kill switch `exam.hub`).** `ExamHubScreen` is the ONE place for every exam someone manages, opened from the Profile tab (`deferredExamHub`), the organization and super admin menus and every "All exams" entry; one `loadAllExams` list, read again on return from any flow (`_flow`). Made plain for a non-technical teacher (D-700 – D-703): the header holds ONE primary New exam (Grade paper sheets and Review grades as labelled ghost actions); **Needs you now** cards (to grade, grading to finish, results to publish, drafts) show only above 0 and open the one exam straight away or narrow the list to theirs; ONE list with three stage tabs **Drafts / Running / Finished** (published with its window over counts as Finished; the archive sits at the end of Finished), search, course, one Filter (how it is sat); each exam reads name · course · type in words, ONE plain sentence (`hubStatusText`, drafts never show a date) and ONE next-step button (`hubNextStep` / `hubNextLabel`), the rest in its ⋯ menu (`hubMenuActions`, never the next step again); the selected exam is a four-step tracker (`HubStep`: Questions · Send or print · Grading · Results) beside the list from 1040 px, its own page (`HubExamPage`) on a phone. `initialTab: 1` opens Finished. Decisions `hub_logic.dart`, drawing `hub_widgets.dart`. Each flow owns its part, and a caller only opens it:
  - `create/`: `openExamCreateWizard`, the ONE new-exam wizard (D-661: Where → Answers → Questions → Bubble sheet → Settings → Students). Answers is "How will students answer?" (`answer_format.dart`: online · on_paper · table · bubble; online = electronic, the rest paper, bubble = paper on a bubble sheet), first so no question is written that the sheet cannot hold (`bubbleCanHold`; a table takes essays too, answered in the booklet); the last format and bubble sheet are remembered per user (`exam_create_prefs.dart`). `exam_create_sync.dart` keeps one server draft, makes the planned versions on Finish and saves `settings.paper_plan`, `answer_format` and `answer_booklet`; Where is skipped when a course is fixed or only one place exists. Paper exams end in Deliver. Questions come from several sources into ONE list (D-717, `question_sources.dart`: written, generated, Google Forms, Excel; imports are `HeldQuestion`s, removed / moved here, edited in the full editor); the ready exam file stays a choice of its own. Copies says what each student gets (`copyPartsOf`, D-716); an own bubble form allows one copy per student.
  - `grade/`: `openGradePapers` (`grade_papers_sheet.dart`, D-660): a course, then Bubble sheets (`deferredBubbleHome`, kill switches `exam.bubble` + `exam.auto_correct`) or Written papers (`openEssayRun`, `exam.essay_run`, D-662); hidden when neither is on.
  - `deliver/`: `openExamDeliver`, preview of the real pages for a real student, Studio, print, email. Opens on `paper_plan` (personal copies or versions), switchable; a plan whose versions were never made gets a one-tap banner. Printed identifiers: `identifier_plan_step.dart` (`settings.print_identifiers`). The preview is `paper_page_replay.dart`, not the `printing` package.
  - `correct/`: `openExamCorrection` decides inside `correctionRouteOf` from the exam's setup: online → `ExamReviewScreen` (marking), paper without bubbles or scanning off → `ExamScansScreen`, bubble → PDF / camera with per-paper review; Finish goes to Get Result. It pushes the page it hands over to and then pops, so the caller's `await` ends when the teacher is really back.
  - `result/`: `openExamGetResult`, one results screen for every kind of exam (publish, Data Lab, export). `hub_degrees_import.dart` + `hub_degrees_import_sheet.dart` (`openHubDegreesImport`, kill switch `exam.results.import`) is the ONE Excel totals import, used by the hub and by Get Result.
  - `revision/`: `openExamRevision`, marks on paper against a Data Lab column or an Excel sheet; the older grade-review links open it too. Tests: `test/org/exam_hub_f1_test.dart` … `f6`.

- **Answer booklet + Fix the key (exam flow v2, D-663 / D-664).** `exam_paper_booklet.dart` (pure: `bookletPlanOf`, `bookletLines`, `bookletSlots`, `BookletWords`) is the answer booklet, drawn by the SAME PDF / Word writers from an `ExamPaperDoc` with `part: PaperPart.booklet`; `PaperPart.questions` is the question paper beside it (no answer room, no table). Deliver reads `answerFormatOf` (`hub/create/answer_format.dart`) through `deliverAnswerFormat`, shows `DeliverSummaryCard` ("What will be printed", the booklet switch) and puts each paper's booklet right after it, one print-plan copy's QR payloads split between them (`splitBookletQr`). `hub/result/key_fix.dart` + `key_fix_sheet.dart`: "Check these keys" on Get Result and "Fix the key" in the item analysis save the key through `PUT /questions/{id}` and call `POST /exams/{id}/regrade`; the engine only re-marks undecided answers with the PINNED version, so no mark moves to the new key yet (limit in D-664). Tests: `test/org/exam_flow_f2_test.dart`.
- **Paper exam flow (D-697 – D-699).** `hub/create/offline_flow.dart` (pure: the four layouts, `recommendedPaperLayout`, `OfflinePlan` = `settings.sheet_plan` v2 and how v1 / plan-less exams read into it), `offline_plan_api.dart` (`PUT …/offline-plan`, `…/attributes`, back contract `OFFLINE_FLOW_CONTRACT.md`), `offline_steps.dart` (the drawn steps: layout cards with schematics, copies, attribute chips, custom attribute form, paper design card, review) and `attributes_step.dart` (the step that owns the attribute calls). `createSteps` in `exam_create_logic.dart` decides which steps apply. Tests: `test/org/offline_flow_test.dart`.

- **Open answers + answer sheets (auto-grade job, D-686 / D-687, contract `../back/docs/grading/AUTOGRADE_CONTRACT.md` A + B).** `exam_open_key.dart` (pure: `OpenKind` number / word / short / long, `OpenKeyExtras` = `answer.kind` / `keywords` / `points` / `match_by`, `DeriveKeyPreview`, `DeriveKeyDebouncer` over `POST /questions/derive-key`) + `exam_open_key_widgets.dart` (`OpenKindChips`, `DerivedKeyStrip`, `OpenKeyAutoPanel`, the one Advanced sheet) are used by `QuickQuestionCard` (quick builder + wizard) and `QuestionEditorForm`; the model answer is the only required input. `hub/create/answer_sheet_plan.dart` (pure: `SheetPlan` = `settings.sheet_plan`, NB2 `POST /exams/{id}/sheets`, `POST /exams/{id}/people/file`) + `answer_sheet_widgets.dart` drive the wizard's Answer sheets step and the Students step's list upload (`createSteps` asks each only when it applies) and Deliver's NB2 card. Scan quality refusals (`kScanRetakeCodes`) are "Retake these pages" in `ScanUploadFailures`. Kill switches `exam.auto_grade`, `exam.answer_sheet`. Tests: `test/org/exam_open_key_test.dart`, `test/org/answer_sheet_plan_test.dart`.
