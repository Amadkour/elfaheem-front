# Testing harnesses

Moved verbatim from the root `CLAUDE.md` (which keeps a short summary and the rules a session must never miss). Keep this file in step with the code.

**API contract test (`test/contract/`)** — scans every path handed to `ApiClient` and checks it against the backend's route snapshot `test/contract/api_paths.json` (`/api/v1/exam/…` against the Exam Engine, `/api/v1/rag/…` against RAG, the rest against the core). After adding a server route, regenerate the snapshot from `../back`: `.venv312/Scripts/python scripts/contract/export_api_paths.py --front ../nextbrain-front` (or `py -3.12`; plain `python` is not on PATH). A call the server deliberately lacks goes in `knownMissing` with a reason; the test also fails when an entry is no longer needed. The same export script writes `test/contract/feature_keys.json`, the kill-switch snapshot that `feature_keys_test.dart` checks (see the features guide in the root `CLAUDE.md`; a key kept out of the catalog on purpose goes in its `notInCatalog` map with a reason). `payload_shapes_test.dart` runs the app's hand-written parsers against REAL server responses in `test/fixtures/payloads/` (every key a parser reads must be in the payload, plus an "older server" variant with the new blocks removed); after a payload change regenerate them with `../back/tests/contract/dump_payloads.py`. `points_wire_test.dart` does the same for the points wallet / live plan / live time against `test/fixtures/points/*.json` (captured by the backend's e2e run); its REQUIRED captures must all be present, so a capture the backend stopped writing fails by name.

**Fake backend and request budgets (`test/support/fake_api.dart`, `test/perf/`)** — `FakeApi` plugs into `ApiClient.instance.dio` as its `HttpClientAdapter` and answers from a route table (`'GET /api/v1/me/home'` → handler; longest prefix wins, a trailing `*` matches by prefix, anything unmatched is FastAPI's bare 404), recording every call with its waterfall depth and the `lib/` frames that issued it. `test/perf/home_requests_*_test.dart` pump each role's real dashboard with the real providers over it and fail when a home makes more requests on open / on pull-to-refresh, more duplicates or a deeper waterfall than `homeBudgets` in `home_requests_harness.dart`; one file per role because the app-wide singletons would carry one role's cache into the next. A change that makes a home cheaper lowers its budget in the same commit. `test/ui/a11y_guidelines_test.dart` runs Flutter's `meetsGuideline` (48×48 / 44×44 targets, labels, WCAG contrast) over the homes, assistant and auth screens; a failure that can't be fixed yet goes in its `_blocked` list with a reason (an entry that no longer fails anything fails the test).

**Visual review renders (`test/visual/`, tag `visual`, NOT a CI suite)** — `flutter test test/visual --update-goldens [--plain-name student]` draws every role's home and the RAG screens at 390×844 and 1440×900, ar/en, light/dark into `test/visual/goldens/*.png` with real fonts and realistic data. They are compared by eye (times follow the clock, so files change every run), not by the test.

`EXPORT_SAMPLES=<dir> flutter test test/org/org_export_test.dart` writes `sample.xlsx`, `sample.docx` and `sample.pdf` into `<dir>`, so they can be opened in Office to check how they render.

`test/ui/layout_harness.dart` (`expectNoLayoutErrors`) pumps a widget at 320×640 and 1400×900, in Arabic and English, with `textScaler` 1.3, and fails on any overflow or layout exception. Use it for new widgets: "no overflow on any screen size" is a project requirement. Widgets that need a platform object (LiveKit `Room`, `VideoPlayerController`) get a plain-values presentational widget next to them (`PreJoinLayout`, `LiveControlBar`, `GuestLiveContent`, `vod_player_parts.dart`) and that is what the harness tests.

Dart test gotchas: a record that holds a list never equals another (`expect((a.list, b), …)` fails) — expect the list on its own; the wildcard pattern is `(_, _)`, not `(_, __)` (lint). `AppConfig.lang` is set in `setUp` and flipped inside a test to check both languages.
