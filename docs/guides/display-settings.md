# Display & reading settings

Moved verbatim from the root `CLAUDE.md` (which keeps a short summary and the rules a session must never miss). Keep this file in step with the code.

- **Display & reading (D-072):** `DisplaySettings.instance` (`lib/core/display/display_settings.dart`, device-local: fonts, headings (Editorial = Markazi Text, the default, or Same as text; D-611, `AppFonts.editorial`), text size × the system's, whole-interface zoom, bold, high contrast, reduce motion, larger targets, reading spacing, presets) is applied by `AppDisplayScope` (`lib/design/app_display.dart`) in `MaterialApp.builder`. Zoom lays the app out at size / zoom, so breakpoints see the smaller width. The page is `DisplaySettingsPage`, entered with `DisplaySettingsTile` next to "Language" (feature key `profile.display`). A new decorative loop (shimmer, pulse, shine) calls `syncMotionLoop(context, controller)` from `didChangeDependencies` so Reduce motion parks it; a loop that tells something (spinner, recording dot) does not. Tests: `test/ui/display_settings_layout_test.dart`; renders: `test/visual/display_golden_test.dart`.

- **Motion (D-580 – D-585):** `lib/design/app_motion_kit.dart` holds every animation the kit applies (page transition, tab entrance, `AppCountUp`, `AppReveal`, `AppDrawIn`, `AppFill`, `AppSkeletonSwitch`, `AppPressScale`, `AppPopIn`, `AppBump`, `AppTilt` / `AppTiltLayer`); all one-shot and all off under `MediaQuery.disableAnimations`. That flag is the person's Reduce motion, the system's, or the Super Admin's `app.animations` key in the disable list (= off for every account, applied live by `AppDisplayScope`, cached for the next start, guests included). New motion goes through the kit, never a raw controller in a screen. Tests: `test/ui/app_motion_kit_test.dart`.
