# Course video player

Moved verbatim from the root `CLAUDE.md` (which keeps a short summary and the rules a session must never miss). Keep this file in step with the code.

**Course video player (`lib/features/sessions/video/`)** — `VideoPlayerScreen(material, playlist:)` is the one player for every caller (session material grid, course profile, downloads); it calls `POST …/materials/{id}/play` itself, plays the encrypted offline copy when `OfflineVideoService.localVariant` has one, and keeps screen protection (`screen_protector`) and wakelock on for the whole visit — switching lectures happens in place (`_openLecture`), never by pushing a second screen. Pure parts (resume logic `VodResume`, `vodPlaylist`/`vodNextOf`, next-up card, lecture list, HUD, captions, skeleton) live in `vod_player_parts.dart` so `test/ui/vod_player_layout_test.dart` can test them without a platform player; the full screen is tested only in its error state with `debugDefaultTargetPlatformOverride = TargetPlatform.iOS` (the Android PiP plugin leaks a timer in tests). Captions are server `.vtt` files (`captions_url`, uploaded by teachers via `POST …/materials/{id}/captions`) and are saved next to offline downloads. On phones swipes change the real screen brightness and media volume (`screen_brightness`, `volume_controller`); elsewhere the player dims/attenuates itself.

Caller buttons (D-312): `VideoPlayerScreen(actions: [VodAction(icon:, label:, onTap:, id:)])` (also on `fromLegacy`) adds glass pills to the top bar (`VodActionButton` in `vod_player_parts.dart`; labels from 720 px, the help button steps aside below 480 px). Records uses it for Open in Studio and Share on a record's signed stream (`RecordPlayerPage`, `lib/features/shared/records/records_share.dart`). `actionsFor: (current) => [...]` adds buttons for the lecture playing NOW (lectures switch in place): the teacher's Open in Studio on a video material (D-315, `session_material_grid.dart`).
