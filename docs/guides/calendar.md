# Calendar and meetings

Moved verbatim from the root `CLAUDE.md` (which keeps a short summary and the rules a session must never miss). Keep this file in step with the code.

**Calendar and meetings (`lib/features/shared/calendar/`)** — ONE schedule page, `SchedulePage` (`schedule_page.dart`, D-085): the student / teacher Schedule tab (`asTab: true`), the top-bar calendar icon and `'/calendar'` (`CalendarScreen` is a thin name for it) all open it. Agenda (phone default) · Day · Week (desktop default) · Month, a mini month, filters by kind / organization remembered on the device, New meeting / Meet now, Export (.ics). Data: ONE `GET /me/calendar?start=&end=[&org_id=]&detail=true` per visible range through `CalendarStore` (`schedule_store.dart`, cached; reloads on `calendar_updated` / `meeting_live` / `session_live` / timetable `attention_changed`), which merges org timetable slots (already expanded to dated events, with exam pauses applied; `detail` adds each changed date's `change` with Accept / Reject, cancelled dates and `pauses`), exams, meetings and course live sessions, plus a personal course's weekly appointments (`GET /student|teacher/schedules`, expanded in the app, never failing the page). Pure logic: `schedule_logic.dart`; plain-value parts: `schedule_parts.dart`, `calendar_views.dart`. Meetings (private, people, department, department head, course group; online via LiveKit or in person) and invitee answers (accept/decline/propose a time) live in `../back/routers/calendar_router.py` + `services/calendar_service.py` + `data/calendar_models.py`. Creating or moving a meeting answers 409 `attendees_busy` unless sent with `force`. A complaint can be turned into a meeting (`POST /orgs/{o}/complaints/{c}/meeting`). A failed weekly-appointments load must never fail the page.
