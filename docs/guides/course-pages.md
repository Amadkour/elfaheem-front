# Course lists, course page, course profile

Moved verbatim from the root `CLAUDE.md` (which keeps a short summary and the rules a session must never miss). Keep this file in step with the code.

**Course lists** — the student's My courses and the teacher's My Courses draw ONE card, `CourseListCard` (`lib/features/courses/course_list_card.dart`, D-102): a row on phones, a 16:9 tile grid from 600 px; the cover carries at most two overlays (Live / Recorded lessons or Draft / Published chip; heart or ⋮); title 2 lines w600, one meta line (`CourseOrgBadge` leads it in a mixed list), a role footer (progress % · price via `coursePriceLabel` · students / sessions / rating). Prices are always `coursePriceLabel` ("EGP 450" in English, "450 ج.م" in Arabic). Header = scope chips / banner + search + segmented filter carrying the counts. Tests: `test/ui/course_list_card_layout_test.dart`, renders `test/visual/course_lists_golden_test.dart`.

**Course page (`lib/features/courses/course_space/`)** — `CourseSpace` is THE course page, shared by the student's course details (`course_detail_screen.dart` + `course_detail_parts.dart`) and the teacher's course studio (`sessions_screen.dart` + `teacher_course_parts.dart`). It takes plain values in slots (hero · spotlight cards · quick actions · tabs, only the active one built · `aside` on wide · `bottomBar` on narrow; the header comment of `course_space.dart` has the phone / desktop layouts) and reads no provider; each role's screen maps its own data into it. A spotlight card with nothing to say returns `SizedBox.shrink()`. **The header (D-940 – D-943)** is one block (`AppBlock(wash: true)`): chips · title (`courseHeroTitleStyle`, never the display size) · one-line subtitle · teacher · progress · the role's ONE call to action (`CourseSpaceHeroData.cta`: teacher New session + Edit + Share, enrolled student Continue, visitor / guest price + Enroll via `courseBuyCta`; left out on a phone with a `bottomBar`, which carries it) · the stats as a grid (a tappable stat is a chip with a chevron; the rating is a stat). The cover is framed at 16:9 and shown whole (`CourseCover`: contained over a blurred copy). Desktop (D-944): the hero spans the full width, then the spotlight cards, the shortcuts as a slim row (`CourseActionRow`), then the tabs with the aside beside them (only when there is one); phones frame the cover inside the block, the bar on the canvas. Price, New session and Edit course appear once per page: no side card or shortcut repeats them. Tests: `test/ui/course_header_layout_test.dart`; renders `test/visual/course_header_golden_test.dart`. Sessions are ONE timeline for both roles, `course_sessions.dart` (plain values, D-102): numbered nodes on a line, states done / up next / live / locked / scheduled, one meta line (kind · AppTime date · length · files); student rows carry progress and Join / Start exam and fold a long completed start; teacher rows a ⋮ menu and reorder. A session title the server generated (`title_auto`) is shown in the reader's language (`sessionTitleOf`). Tests: `test/ui/course_space_layout_test.dart`, `course_detail_layout_test.dart`, `teacher_course_layout_test.dart`; renders in `test/visual/course_space_golden_test.dart`.

**Online meetings on the teacher's Sessions tab (D-1723 – D-1726)** — above the timeline, `CourseMeetingActions` (course_sessions.dart): **Meet now** (`startQuickMeeting(courseId:)`: a live meeting with the course's students, starting at once) and **Repeating meeting** (the meeting form with the course preset, online, a weekly repeat on); each hides with its kill switch (`live.quick_meeting`, `calendar.recurring`). Under it `CourseSeriesSection` lists the course's series; the owner of an online one gets Copy guest link · Link options — the series' ONE guest link, the same URL for every date (`docs/guides/calendar.md`). Tests: `test/ui/course_meetings_test.dart`, `course_series_block_test.dart`.

**Course profile (`lib/features/courses/course_profile/`)** — Since D-111 its parts are TABS of the one course page (`course_profile_hub.dart`: `CourseProfileHub` loads `GET /course-profile/{id}` lazily when a profile tab opens; `courseProfileTabs` gives the student Announcements · Progress · (Archive) and staff Announcements · Attendance · Team · Archive; `CoursePageLoader` is what `openCourseProfile`, `/course-profile` and `course_profile` notifications open). `CourseProfileScreen` remains only for an earlier run (read-only) and as the fallback. TAs work on sections/labs only unless the instructor grants more; archived courses are read-only. Backend: `../back/routers/course_profile_router.py` (incl. course announcements), test `tests/org_v2/e2e_course_profile.py`.

**Overview (D-1090, owner's A2 pick)** — the course page opens on its own dashboard: `courseOverviewTab` (course_profile_hub.dart) draws `CourseOverview` (`course_space/course_overview.dart`, plain values) from the `page` block of `GET /course-profile/{id}` (`CourseProfile.page`, `course_page_models.dart`; an older server leaves it null and the tab says so). Cards: Appointments (Lectures / Sections; staff get the section-group chips; a student sees only the lectures and their own section — the server filters, the card never offers another group), Weekly schedule, Exams, Course rules (kill switch `course.rules`), Attendance, Team, and for a course outside any organization Reviews and After this course. The spotlight carries the ONE highlighted `CourseNextCard` and the thin `CourseSetupBar` (staff, until 5/5); the old quick-action strip is gone (Data Lab, My analytics and Support are in the ⋮ menu). Editors: `course_page_sheets.dart` (rules, sections, a student's one-time pick); the organization's `section_mode` is a switch in the academic settings (whole-object PUT). Tests: `test/ui/course_overview_layout_test.dart`, the `course_page_*` payloads in `test/contract/payload_shapes_test.dart`.
