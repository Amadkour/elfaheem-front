## Facts

1. Embedder `multilingual-e5-small@int8` (ONNX Runtime, dim 384, max 512, query:/passage: prefixes); reranker `mmarco-mMiniLMv2-L12-H384-v1@int8` (max 384, batch 16, optional); generator `qwen3-0.6b@int4` (1.7B registered) on `onnxruntime-genai==0.18.0`; **no torch** anywhere.
2. Ingestion `ingest/extract.py`: pdf (pypdfium2 + OCR), docx, html, md, txt, image (OCR); limits 30 MB / 600 pages; `library.py:upload` → `jobs` → `worker.py` (`rag-worker`, ingest only) → `run_ingest` (extract → clean → chunk → embed with `embed_cache` → version swap); status queued | processing | ready | failed | archived, version chain by `family_id`, per-org quota.
3. Persistence: ONE table `queries` (question, answer, citations, retrieved, trace, follow_ups, stage, feedback, visibility JSON, latency_ms). No conversations, no retention.
4. Numbers (`docs/CAPACITY.md`, `bench/rag`): recall@5 0.958–0.965, cross-language 0.91, not-found balanced acc 0.761 (265 q); Qwen3-0.6B INT4 ≈ 10 tok/s, one answer 9–15 s (prefill 400–550 + 30–130 out); 1.7B ≈ 3.5–4 tok/s, 37–71 s; 4 threads slower than 2; retrieval 1.6 s p50 / 1.9 s p95 (20 reranker pairs); ingestion 45–83 ms/chunk.
5. Scope: client sends `{app: true, org_id?}` (`app_assistant.dart:appAssistantOrg`); `_context` → app docs only, or app docs OR the org library the member may read (never personal course material); enforced in SQL and RLS; `course_id` with app → 422 `app_context_only`. **No tenant mixing found.**
6. Docker: one `python:3.12-slim` image for core + exam + rag + workers; compose `rag` (:8002), `rag-worker` (ingest, 2 g / 1 CPU), `rag-worker-ask` (questions + drafts, 3500m / 2 CPU, generator loaded); models at `/app/models` (qwen3-0.6b 512 M, qwen3-1.7b 1.4 G, e5 578 M incl. fp32, mmarco 579 M incl. fp32 — fp32 variants double the volume).
7. Routes: admin `/api/v1/rag/admin` GET/PUT `/settings`, POST `/llm/test`, GET `/overview`, `/queries`, `/queries/{id}`, POST `/playground`, GET `/exam-drafts`; library `/documents` CRUD + `/reindex`, `/orgs/{id}/settings|quota`, `/starters`, `/ask`, `/queries/{id}`, `/queries/{id}/feedback`, `/orgs/{id}/answers/feedback`, `/queries`, `/app/documents/sync`, `/exam-drafts`.
8. Client `RagChatView` has: starters, stage trail, `[n]` citations, follow-ups, thumbs (no comment box), flat history (newest 20), per-org reset. Missing: new chat, session list, streaming, "report unanswered".

## Ranked plan (Track E)

1. **Curated Q&A layer** `rag.qa_pairs` (scope app | org, variants ar/en, answer, deep link, e5 embedding via `embed_cache`), matched in `pipeline.run` before `search()`; thresholds calibrated on `bench/rag` (high → direct answer, medium → examples in the prompt); admin CRUD next to `/documents`; "promote to Q&A" on the overview's not_found / unhelpful lists.
2. **Answer cache** `rag.answer_cache` keyed by sha256(normalised question, scope key, max(document.updated_at) of the visible set, generator ref); checked in `chat.run_ask`; invalidated by library / Q&A version.
3. **Budget cut** for light: `LIGHT_SOURCES` 4 → 3, `LIGHT_SOURCE_CHARS` 1200 → 800, planned queries ≤ 2, `CANDIDATES` 40 → 20 (≤ 30 reranker pairs), token-count guard before prefill.
4. **Real BM25 on Postgres** (`rank_bm25` over top-N tsv matches) so PG matches the SQLite path the benchmark was tuned on. Arabic normalisation in the tokenizer (diacritics, alef / yaa / taa-marbuta variants).
5. **Conversations** table + `queries.conversation_id`; routes POST / GET / PATCH / DELETE `/conversations`; `history_of` uses the conversation; retention tick in the worker (prune trace / retrieved after N days, delete conversations after M, admin-configurable, default 90 days); client "new chat" + session drawer, `RagApi.history` kept as fallback.
6. **Data-driven router**: `GLOSSARY` + intent rules in `platform_settings` (editable in the console); keyword → deep link / canned answer seeded from `data/app_features_guide.json`.
7. **Answer eval** `bench/rag/run_answer_eval.py`: citation precision, faithfulness (`lexical_check`), not-found correctness on the 265 q + a new 40–60 q set over the real app guide / terms corpus (ar + en, edge cases, out of scope, the questions that failed in production); tokens/s + p50/p95 per model → `results.json`; CPU benchmark ONNX INT4 vs llama.cpp GGUF (Q4_K_M / Q5) for 0.6B and 1.7B, choose by measurement.
8. **Image / UX**: fetch only INT8 / INT4 variants in production; stream partial answers (every N tokens into `queries.stage`/`answer`, surfaced by `RagStageTrail`, later over the Track D SSE); monitoring counters (latency, cache hit, direct-QA hit, no-answer rate) in `overview` → super admin dashboard.

## Baseline diagnosis (E.1, 2026-10-28)

71 questions over the real corpus: retrieval@5 96 %, 0 leaks, not-found 100 %, injection 100 %. Answer correctness 52 % (extractive) / 59 % (qwen3-0.6b). Losses: the not-found gate (threshold 7.31 + runner-up margin, calibrated on the synthetic bench) rejects 17 / 10 right answers because ar/en twins of one section split the margin and short terms / about sections score low; the 0.6B light writer fails 17 / 48 calls and answers from the wrong sentence in 10; no small-talk path without the model. Latency on the laptop 3 s / 22 s p50. Full tables in `../back/bench/rag/answer_eval/results/`.

## Status (E.8, 2026-10-28)

Partial answers: the local generator hands its output so far to `llm.streaming()` (`mlkit/generator.py` `on_text`, every 8 tokens / 300 ms); `pipeline.LightStream` shows the light writer's answer part only after the quote is complete, in the sources and on topic, and retracts it when the checks reject the reply; the worker writes it to `queries.answer_partial` (rag_0013, same row / RLS) and sends `job_updated{kind: rag_query, status: running, stage: write, partial_len}` at most once a second. The app's `RagAnswer.partial` / `provisional`, `RagPartialAnswer` (muted draft, caret steady under reduced motion) under the stage trail, replaced by the final answer; `waitFor` polls every 1.5 s while a draft grows without the live stream. Plain-text replies, hosted models, the answer cache and curated Q&A stream nothing. Tests: `../back/tests/rag/e2e_rag_stream.py`, `test/org/rag_partial_test.dart`, `test/ui/rag_partial_layout_test.dart`. Owed: a real-model check of the time to the first partial (the quote comes first, so the draft starts after ≈ 60–110 output tokens).
