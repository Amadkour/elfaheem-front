# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Flutter education platform (VOD courses, live sessions, attendance, organizations) — package name `flutter_education_app`, Firebase project `elfaheem`, backend at `AppConfig.baseUrl` (`https://nextbrain.site/api` unless built with `--dart-define=API_BASE_URL=…`; a release build accepts only an `https://` override, see `resolveApiBaseUrl`). Targets Android, iOS and Web (web is deployed to Firebase Hosting from `build/web`). Default UI language is Arabic (RTL); English is also supported.

## Commands

```bash
flutter pub get
flutter analyze --no-fatal-infos --fatal-warnings   # the CI gate (exit 0 = no warnings/errors); lints: package:flutter_lints/flutter.yaml; platform dirs are excluded
flutter run                          # add -d chrome for web
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:18080/api   # Android emulator → local stack (../back/scripts/dev/setup.*, demo accounts in ../back/README.md); web / iOS simulator use http://localhost:18080/api, a USB phone after `adb reverse tcp:18080 tcp:18080`; default is production
flutter test test/org/ test/export/ test/ui/ test/auth/ test/perf/ test/contract/   # the real suites (CI runs them all); test/widget_test.dart is the stock counter template and fails
flutter test test/some_test.dart --plain-name "name"   # run a single test
flutter build web && firebase deploy --only hosting
scripts/build_release.sh apk|appbundle|ipa|web   # release builds (bash): obfuscated, symbols in build/debug-info/<version>/ (keep them: `flutter symbolize -i trace.txt -d build/debug-info/<version>/app.android-arm64.symbols` is the only way to read a stack trace); signing from android/key.properties / env (never committed)
dart run flutter_launcher_icons      # regenerate app icons
dart run flutter_native_splash:create  # regenerate splash screens (android/ios drawables + assets/images/splash*.png)
```

CI (`.github/workflows/ci.yml`, Flutter 3.47.7 stable) runs on pushes to `production`, `main` and `feature/**` and on every pull request — a push to any other branch (e.g. `organizations`) runs nothing until a PR is opened. It gates on: 0 analyzer warnings/errors (plain `flutter analyze` exits 1 on info lints, which are allowed — use the flags above, or count `" warning - "` / `" error - "` lines), the test suites above, `flutter build web --release`, and gitleaks over the tree and the new commits (`.gitleaks.toml`: an allowlist entry must match rule AND path AND value, with a reason).

**API contract test (`test/contract/`)** — scans every path handed to `ApiClient` and checks it against the backend's route snapshot `test/contract/api_paths.json` (`/api/v1/exam/…` against the Exam Engine, `/api/v1/rag/…` against RAG, the rest against the core). After adding a server route, regenerate the snapshot from `../back`: `.venv312/Scripts/python scripts/contract/export_api_paths.py --front ../nextbrain-front` (or `py -3.12`; plain `python` is not on PATH). A call the server deliberately lacks goes in `knownMissing` with a reason; the test also fails when an entry is no longer needed. The same export script writes `test/contract/feature_keys.json`, the kill-switch snapshot that `feature_keys_test.dart` checks (see the features guide below; a key kept out of the catalog on purpose goes in its `notInCatalog` map with a reason). `payload_shapes_test.dart` runs the app's hand-written parsers against REAL server responses in `test/fixtures/payloads/` (every key a parser reads must be in the payload, plus an "older server" variant with the new blocks removed); after a payload change regenerate them with `../back/tests/contract/dump_payloads.py`.

**Fake backend and request budgets (`test/support/fake_api.dart`, `test/perf/`)** — `FakeApi` plugs into `ApiClient.instance.dio` as its `HttpClientAdapter` and answers from a route table (`'GET /api/v1/me/home'` → handler; longest prefix wins, a trailing `*` matches by prefix, anything unmatched is FastAPI's bare 404), recording every call with its waterfall depth and the `lib/` frames that issued it. `test/perf/home_requests_*_test.dart` pump each role's real dashboard with the real providers over it and fail when a home makes more requests on open / on pull-to-refresh, more duplicates or a deeper waterfall than `homeBudgets` in `home_requests_harness.dart`; one file per role because the app-wide singletons would carry one role's cache into the next. A change that makes a home cheaper lowers its budget in the same commit. `test/ui/a11y_guidelines_test.dart` runs Flutter's `meetsGuideline` (48×48 / 44×44 targets, labels, WCAG contrast) over the homes, assistant and auth screens; a failure that can't be fixed yet goes in its `_blocked` list with a reason (an entry that no longer fails anything fails the test).

**Visual review renders (`test/visual/`, tag `visual`, NOT a CI suite)** — `flutter test test/visual --update-goldens [--plain-name student]` draws every role's home and the RAG screens at 390×844 and 1440×900, ar/en, light/dark into `test/visual/goldens/*.png` with real fonts and realistic data. They are compared by eye (times follow the clock, so files change every run), not by the test.

`flutter_webrtc` is overridden to a fork (`github.com/Amadkour/flutter-webrtc`) in `dependency_overrides`, pinned to a commit `ref:` (change it on purpose, D-010); `screen_protector` is pinned to 1.5.1 on purpose (see the pubspec comment). Don't add the `excel` package: it forces `archive` 3.x, which downgrades `image` and `flutter_launcher_icons`. That's why every Excel/Word file is written by hand on top of `archive` 4. When adding a package, check that `pubspec.lock` gains only that package and nothing gets downgraded.

`EXPORT_SAMPLES=<dir> flutter test test/org/org_export_test.dart` writes `sample.xlsx`, `sample.docx` and `sample.pdf` into `<dir>`, so they can be opened in Office to check how they render.

`test/ui/layout_harness.dart` (`expectNoLayoutErrors`) pumps a widget at 320×640 and 1400×900, in Arabic and English, with `textScaler` 1.3, and fails on any overflow or layout exception. Use it for new widgets: "no overflow on any screen size" is a project requirement. Widgets that need a platform object (LiveKit `Room`, `VideoPlayerController`) get a plain-values presentational widget next to them (`PreJoinLayout`, `LiveControlBar`, `GuestLiveContent`, `vod_player_parts.dart`) and that is what the harness tests.

Dart test gotchas: a record that holds a list never equals another (`expect((a.list, b), …)` fails) — expect the list on its own; the wildcard pattern is `(_, _)`, not `(_, __)` (lint). `AppConfig.lang` is set in `setUp` and flipped inside a test to check both languages.

The code is not `dart format`-ed (formatting `lib/features/org` would rewrite every file). Don't run `dart format` on files you edit: it buries the real change in thousands of lines of re-wrapping. New files are written formatted by hand (D-003).

Docs: `D-nnn` references point to `docs/DECISIONS.md` (design decisions and deliberate deviations; add one when you deviate). `docs/ARCHITECTURE.md` is the long-form architecture. The root `PROGRESS.md` is the live tracker of the current multi-session job (platform polish on `feature/platform-polish` in both repos): on a resume, read it first and continue the first task not `done`/`verified`; its per-track analyses are in `docs/polish/`. Live work (LiveKit room, recording, performance) resumes from `docs/live/NEXT_SESSION.md` instead: its §1 is the next task. `docs/PROGRESS.md` is the older phase log of the RBAC/exams/RAG refactor (history), `TIMETABLE_NOTES.md` the running notes of the timetable rebuild, `docs/AUDIT.md` / `docs/SECURITY_SCAN.md` dated read-only audit reports (their backend halves are in `../back/docs/`), and `documents/` holds developer guides and slides (Word + PowerPoint per topic, generated from both repositories by `documents/_build/build_*.py` on top of `_build/nbdoc.py`; rebuild them after a large change, see `documents/README.md`). Guides — the feature deep-dives moved out of this file, read the one you work on: `docs/guides/` (`home-screens.md`, `course-pages.md`, `video-player.md`, `calendar.md`, `export-studio.md`, `boot-splash.md`, `auth-biometric.md`, `display-settings.md`, `keyboard.md`, `native.md`, `org-dashboard.md`, `paper-exams-omr.md`); the rest of org, live, exam and RAG are in the folder `CLAUDE.md` files (`lib/features/org/`, `lib/features/teacher/sessions/live/`, `lib/features/shared/live/`, `lib/features/shared/exam_engine/`, `lib/features/shared/rag/`), loaded when you work there.

## Architecture

**Startup (`lib/main.dart`)** — `_bootstrap()` paints a boot splash immediately, runs `_initCore()` (storage, `assets/translation.json`, Firebase, Remote Config, connectivity, offline videos, …) with each step wrapped in `_safe(name, fn, seconds:)` timeouts so one slow service never blocks launch, then runs the real app. The splash is `lib/design/boot_splash.dart` (`BootSplash`, details in `docs/guides/boot-splash.md`). Only a storage failure shows `_FatalApp`. Routing is a single `onGenerateRoute: _router` switch over named routes; the initial route comes from `MyAuthProvider.homeRoute`, which maps the user role (`admin`/`super-admin`/`developer` → `/admin_dashboard`, `teacher`, `parent`, `org-admin`/`org-staff` → `/org_dashboard` (every non-student org role, even one who manages nothing, D-103); otherwise student `/dashboard`). An org-admin/org-staff who last left the organization for their personal account starts on `/dashboard` (remembered per user). Offline start-ups route to `/downloads` (or student dashboard + downloads on top).

**Features (`lib/features/<role>/`)** — `student`, `teacher`, `parent`, `admin`, `org`, plus `shared` (attendance, notifications, profile, subscription, downloads, upload, guest, calendar, course_profile, exam_engine, rag, inbox, passcode, …), `auth`, and `ads` (`ads_pages.dart`: the home slider, the super admin's ads page with teacher-ad approval, and the teacher's own ads). Each role has its own dashboard screen.

**Home screens and badges** — every role's home is built from `lib/design/home_kit.dart` and kept short and calm (D-102). Its data is ONE call, `GET /api/v1/me/home` (`MeHomeService.instance`); badge counts are ONE call, `GET /api/v1/me/attention` (`AttentionService.instance`), drawn with `AttentionBadge(tabKey: AttentionTabs.x, …)`; a new tab key goes in `AttentionTabs` AND the server's `TABS` (`../back/services/attention_service.py`). Layout, type weights, density rules, Go live, Live now: `docs/guides/home-screens.md`.

**Course lists, course page, course profile** — both roles' course lists draw ONE card, `CourseListCard`, and prices are always `coursePriceLabel`; `CourseSpace` is THE course page (plain values in slots, reads no provider) with ONE sessions timeline, `course_sessions.dart`; the course profile is one screen for every role. Details: `docs/guides/course-pages.md`.

**Course roadmap + recommendations (`lib/features/shared/roadmap/`, D-120)** — personal accounts on personal courses ONLY: an account in an organization (org-admin / org-staff, or a live membership while organizations are on) gets neither, and an organization course has no roadmap (server: `../back/services/learning/access.py`, 403 `individual_only` / `org_course` / `feature_off`; app: `roadmapOrgAccount`, `roadmapHiddenError` draws nothing). `roadmap_api.dart` is the pure part (models, `RoadmapDraft`, API: `GET/PUT /api/v1/roadmap/courses/{id}`, `/me/recommendations`, `/me/learning-prefs`, `/me/journey`). The course page's "Path" tab (`roadmap_tab.dart`, both roles) draws ONE vertical path (`roadmap_path.dart`: previous → "You are here" → next in order with prerequisite ✓ / ○ chips) and the teacher's editor sheet (`roadmap_editor.dart`: next courses = the same `course_next_steps` as the course form, advisory prerequisites, level, topic words). The backend's hybrid engine (`../back/services/learning/scoring.py`, pure; `recs.py` caches per student) feeds "Recommended for you" on the profile (`recommendations.dart`, a reason per course, "Not interested", interests sheet); the teacher's path and the engine's list never mix. The student home has ONE journey card (`lib/features/student/home/home_journey.dart`) from `/me/home`'s `journey` (no request of its own; null → no card), swept by `AppShineBand` (`lib/design/app_shine.dart`, the attendance entry's band, parked by Reduce motion) → `JourneyPage`. What the lists do is reported in batches (`RecEventLog`) and the super admin reads it per reason and tunes the four weights on `AdminRecommendationsPage` (`lib/features/admin/admin_recs_page.dart`). For a personal course the course form links to the Path editor instead of its own next-courses field and never sends `next_course_ids` (it would undo the Path tab); level / topic words are in both. Kill switches `roadmap` · `roadmap.path` · `roadmap.recommendations` · `roadmap.journey` · `course.enroll_roadmap` · `admin.recommendations` (`roadmapOff` also checks the root). Tests: `test/org/roadmap_test.dart`, `test/ui/roadmap_layout_test.dart`; backend `tests/org_v2/e2e_learning_roadmap.py`, `recs_unit.py`.

**Real-time (`lib/core/live/`, Track D)** — `LiveEventsClient.instance` holds ONE Server-Sent Events stream, `GET /api/v1/me/events`, and feeds it into `LiveEvents.instance`, the same bus the silent FCM pushes use, deduplicated by event id. The stream is open only while signed in, in front and something has called `bind()`. It reconnects with backoff and `Last-Event-ID`, and a 401 retries once through `POST /me/events/ticket`. A screen that waits on a job or watches a list must not poll on a timer: use `EventOrPoll` (timer style) or `JobWatch` (`await`-loop style) from `event_wait.dart`, which run on the event and keep a slow poll only as the fallback. Tests: `test/org/live_events_client_test.dart`, `event_wait_test.dart`, and `live_events_soak_test.dart` (soak; the real-server run is opt-in).

**Navigation glue (`lib/utils/widget/`)** — `AppNavigator` (`app_navigator.dart`) is the one place that opens a "module" from a notification tap, a push, a dialog button or a shared link, always through `navigatorKey` from `main.dart`; add new deep-link targets there rather than in each caller. `DeepLinkService` (`deep_link_service.dart`) handles course share links `https://nextbrain.site/c/<courseId>?ref=<sharerUserId>`, which Flutter's default deep linking feeds to `onGenerateRoute` as `/c/<id>?ref=<uid>`. `VersionCheckService` (`lib/core/version_check_service.dart`) runs once at startup against `GET /app/version-check` and shows a blocking (`must_update`) or dismissible (`should_update`) dialog. The rest of `lib/utils/widget/` is the older widget set (`BasePage`, `ParentComponent`, `PrimaryButton`, `AppBar`, text fields, …) that existing screens still use; new UI comes from `lib/design/` (below), which wraps and re-exports what it needs from there.

**State** — `provider` package. All app-wide `ChangeNotifier`s are registered in `lib/core/providers.dart` (`appProviders`); add new global providers there. Feature providers extend `BaseProvider` (`lib/core/base_provider.dart`) and wrap API calls in `run(() => ...)`, which manages `ProviderState` (idle/loading/success/error), sets `errorMessage`, and does one outer retry. Some app-wide state uses singletons (`XService.instance`, `ViewAsState.instance`, `AppConnectivity.instance`).

**Networking (`lib/core/api_client.dart`)** — `ApiClient` is a singleton (`ApiClient()` returns `ApiClient.instance`) on Dio, with `get/post/put/patch/delete/postForm/postMultipart`. Things it does for every request:
- Throws only `ApiException` (`message` is safe to show to the user; `code` holds server codes such as `DEVICE_MISMATCH`, `VIEW_LIMIT_REACHED`). In UI: `ApiException.from(e).message`.
- Refreshes tokens and redirects to login on 401. Tokens live in `lib/core/token_storage.dart` (secure storage on mobile, SharedPreferences on web); `POST /auth/refresh` sends the refresh token in the body and returns a NEW pair, which is stored (rotation: an old token is dead after one use). `StorageService` keeps only the cached user and UI preferences.
- App-layer envelope encryption (X25519 → HKDF → AES-256-GCM, `{"n","ct"}` bodies) and certificate pinning on mobile (`_pinnedCertSha256`). Server cert rotation requires updating the pin list.
- Sends device-ID headers (device binding / blocked-device dialog lives in `features/student/courses/security/`).
- Adds `X-View-As: <id>` while super-admin "view as" mode is active (`utils/widget/view_as_state.dart`).
- Adds `X-Onboarding-Token` to teacher onboarding routes (`isTeacherOnboardingPath`; token kept in memory by `lib/features/auth/teacher_onboarding_token.dart`), and opens `AdminMfaPage` on 403 `mfa_enrollment_required` (`shouldOpenMfaEnrollment`: never two at once, again only 30 s after the user left it). Debug request logs go through `redactForLog`: add any new secret field to `logSensitiveKeys`. MFA files: `docs/guides/auth-biometric.md`. Every method takes an optional `headers:`.
- Fingerprint / Face ID sign-in (D-082, never web, kill switch `auth.biometric`): `lib/features/auth/biometric.dart` + `biometric_widgets.dart`; details in the same guide.
- Maps 503 `server_busy` (the Exam Engine / RAG in-flight cap) to `ApiMessages.serverBusyAr/En`; coded errors outside org screens get bilingual text in `lib/core/api_error_text.dart` (`apiErrorText`).

Cleartext is refused on devices except `127.0.0.1` / `localhost` (the offline-video loopback server) and `10.0.2.2` (emulator → local stack): `android/app/src/main/res/xml/network_security_config.xml` and iOS `NSAllowsLocalNetworking` (D-010). Every server, media and LiveKit URL must be https / wss.

**Exam Engine, RAG and the app assistant** — separate backend services (`../back/exam_engine`, `../back/rag_service`) reached through the same `ApiClient` under `/api/v1/exam/…` and `/api/v1/rag/…`; the details are in `lib/features/shared/exam_engine/CLAUDE.md` (engine calls, exam taking, quick exam, generated questions, printable papers, scanned sheets, offline sittings) and `lib/features/shared/rag/CLAUDE.md` (the floating app assistant, the model pipeline, the Super Admin's console, the features guide). Paper exams with bubble sheets (D-150 – D-160, the decisions are in `../back/docs/DECISIONS.md`) — the setup wizard, scanner, sheet types, review and results in `lib/features/shared/exam_engine/paper/` (`exam_setup*`, `scan/`, `templates/`, `review/`), the student's identifier dialog in `lib/features/shared/identity/`, end to end in `docs/guides/paper-exams-omr.md`. The super admin's AI Models page and the floating model-download bar are `lib/features/admin/models/` over `lib/core/models_hub/` (the model hub's API at `/api/v1/models/…` + `ModelDownloads.instance`; `ModelDownloadsHost` sits in the `MaterialApp.builder` stack), kill switch `models.admin`. Rules for every feature: **when you add a user-facing feature, add it to `../back/data/app_features_guide.json`** (group, roles, Arabic + English name, summary, place, steps, the kill-switch keys that hide it — D-052), and **a new kill-switch key** goes into `../back/services/feature_catalog.py`, then regenerate the snapshots (same command as the API contract test): `test/contract/feature_keys_test.dart` fails on a key the catalog lacks, because a super admin could never switch it off.

**Server-driven theme & feature flags** — `ThemeConfigProvider` (`lib/config/theme/`) loads the theme from `GET /api/v1/theme/{platform}` and builds `materialTheme()`. Always read colors via `context.colors`, never hard-coded colors. The same response sets `AppConfig.disableList` (feature kill-switch ids, e.g. `profile.logout`, `teacher_tab_analysis`). To make UI switchable, wrap it in `ParentComponent(featureKey: '...')` (hides it), or give a `BasePage` a `ValueKey('<id>')` (shows a "coming soon" page). `AppConfig.setDisableList` rebuilds the whole widget tree when the list changes.

The disable list has layers. The effective list combines:
- the platform list from the theme response;
- the open organization's list (`AppConfig.setOrgDisableList`);
- `AppConfig.orgEntryKeys`, while the super admin has organizations switched off (`AppConfig.orgsEnabled` / `setOrgsEnabled`, from `orgs_enabled` in the theme response).

A super-admin OFF always wins, because an organization can only add keys. Hidden features disappear rather than greying out. With organizations off, the server answers 403 `orgs_disabled` on org routes, and `/org_dashboard` is wrapped in `OrgsGate`. The theme response's `platform_settings` also sets the platform timezone and 12h/24h (`AppTime.configurePlatform`).

**UI kit** — New screens should use `lib/design/app_kit.dart` (role-neutral aliases over the Data Lab / org / admin widgets: `AppHero`, `AppCard`, `AppStatTile`, `AppEmpty`, `AppListSkeleton` rather than spinners, `AppBanner`, `AppField`, `showAppSheet`, `appConfirm`, …; the header comment of that file has the full usage table) and wrap pages in `BasePage` (`lib/utils/widget/base_page.dart`), which handles the background, kill-switch, and the global upload-progress footer. App-wide rules the kit enforces:
- **Tokens (D-103):** spacing, radii, motion, touch targets, shadows and type roles come from `lib/design/app_tokens.dart` (`AppSpace.md`, `AppRadius.card`, `AppMotion.of(context).base` — zero under Reduce motion, `AppTouch`, `AppType`), never a raw number in a screen.
- **Switches:** only `AppSwitch` / `AppSwitchTile` (`app_switch.dart`), never `Switch`/`SwitchListTile`.
- **Dropdowns:** only `AppDropdown`.
- **Fonts (D-072):** never write a family name in a TextStyle. Use `appText(...)`, the theme's styles, or `fontFamily: AppFonts.family` (`AppFonts.display` = the same font, bold at every weight) from `lib/core/display/app_fonts.dart`: the person picks one font per language (premium OFL catalog; defaults IBM Plex Sans Arabic / Inter, pubspec fonts; the others are `assets/fonts/ui/<id>/` loaded by `FontLoader` when chosen). A `static final` / `const` TextStyle would freeze the font: make it a getter. Documents (PDF / Word / certificates / the export designer) keep their own embedded fonts.
- **Display & reading (D-072):** `DisplaySettings.instance` (device-local) is applied by `AppDisplayScope` in `MaterialApp.builder`; zoom shrinks the width breakpoints see. A new decorative loop (shimmer, pulse, shine) calls `syncMotionLoop(context, controller)` from `didChangeDependencies` so Reduce motion parks it. Details: `docs/guides/display-settings.md`.
- **Direction-sensitive icons:** `arrow_back/forward`, `chevron_left/right`, `arrow_*_ios`, `navigate_*`, `send`, `open_in_new` mirror in Arabic by themselves, so never pick one by language (it flips twice). `logout`, `login`, `exit_to_app`, `subdirectory_arrow_*`, `north_east` and `arrow_outward` do not mirror: use `DirIcons` (`lib/design/app_icons.dart`). Use `CupertinoIcons.back` / `forward`, not `chevron_back` / `chevron_forward`. `test/ui/rtl_icons_test.dart` reads `lib/` for both mistakes.
- **Displayed times and dates:** always go through `AppTime` (`lib/core/app_time.dart`, re-exported by the kit), which applies the platform or organization timezone and the 12h/24h choice. `AppTime.configureOrg` is set when an organization is opened and cleared when it is left.
- **Table exports:** use `showAppExportSheet(context, AppTableExport)` (`app_table_export.dart`, writers in `lib/design/export/`). It offers Excel, Word and PDF with a column picker, RTL and Arabic fonts, and remembers the last choice per table. Admin `PagedList`s take an `export:` option that fetches every page before exporting. It is the Export Studio (D-130 – D-134): build the export inside `bilingualExport(() => …)` so English / Both files get English headers; the designers share ONE engine, `lib/design/studio/`; the server's certificate font list is the renderer's catalog, never a second list. Server datasets, share links, certificates, kill switches: `docs/guides/export-studio.md`.
- **Role shells:** every role dashboard is `AppShell(width:, currentIndex:, onTap:, items:)` over `DashboardItem`s (`lib/design/app_shell.dart`, D-062): `Breakpoints.shellFor` picks sidebar / rail / bottom bar, and a tab's count is its `badge` (what the attention feed lacks) + the live count of its `attentionKeys`, drawn by `ShellBadge` at the leaf — never a shell-level `AttentionService` listener. Tabs are lazy (`LazyTabStack`, D-077): a tab is built on its first visit and kept, so a tab must not assume it loaded at app open. Hero / sidebar ink uses the on-hero roles (`c.onHero`, `onHeroMuted`, `heroGlass`, `heroGlassBorder`, `heroEnd(base)`, `heroTint(base)`), never `Colors.white` / `Colors.black`.
- **Charts:** `lib/design/app_charts.dart` (`AppTrendTile`, `AppBarChart`, `AppDonut`, `AppSparkline`, `AppLegend`, `appCompactNumber`), pure CustomPaint with the theme-derived palette (D-063) — no chart package.
- **More / settings pages:** `AppSettingsPage` + `AppSettingsGroup` / `AppSettingsTile` / `AppSettingsHeader` (`app_settings.dart`): grouped cards, a search field once a page holds more than 8 tiles, `featureKey:` per tile; the admin and parent More pages use it, the old `SettingsGroup` / `SettingsTile` still work elsewhere.
- **Keyboard (web / desktop):** `AppKeyboardSupport` (`lib/design/app_keyboard.dart`, D-012) gives every text field Enter → next field / the form's primary button, Ctrl+Enter, Esc and Ctrl+K or "/" → search: nothing to wire on a new screen; `EnterSubmits(onSubmit:)` / `EnterSubmits.none` where the guess would be wrong. Details: `docs/guides/keyboard.md`.

**Cross-cutting helpers (easy to miss, use them instead of rolling your own)** —
- `showAppNotice(text, error:)` (`lib/design/app_notice.dart`) for every toast: it is drawn in the root Navigator's overlay, so it stays visible above sheets and dialogs where a `SnackBar` is hidden. New code uses it rather than `ScaffoldMessenger` / `SnackBar` (a few older screens still do).
- `AppEmailField` / `AppPasswordField` / `AppPhoneField` / `AppUrlField` (`app_inputs.dart`) are the identity inputs with validation and bilingual messages; login and forgot-password keep their single identifier field on purpose.
- `AppHScroll` (`app_hscroll.dart`) wraps wide tables / grids so they scroll with a mouse on web and desktop; `AppScrollBehavior` is set on `MaterialApp.scrollBehavior` already.
- `showAppImageCropper(context, bytes, shape:)` (`app_image_cropper.dart`) is the one cropper (avatars, covers, logos), pure Flutter, works on web.
- `LiveEvents.instance` (`lib/utils/live_events.dart`) is the in-app event bus: `NotificationService` (`features/shared/notification/notification_service.dart`, FCM + local notifications, the top-level background handler) turns a silent push into a `LiveEvent`, as does the SSE stream above, and screens subscribe with `listen({LiveEvents.complaints}, …)`. Event names must match `../back/services/live_update_service.py`. A visible push tap goes through `AppNavigator`.
- `topRouteObserver` (`lib/utils/top_route_observer.dart`) is the single `NavigatorObserver` (installed once in `main.dart`): every push / pop tells `AttentionService` to refresh, and its connectivity listener emits `LiveEvents.connectivity`, kicks the offline attendance / exam syncs on reconnect and keeps the downloads shortcut — hook route- or reconnect-dependent work there, not in individual screens.
- `AppIdentity.instance` (`lib/core/app_identity.dart`) is the admin-set name / tagline / logo from the public `GET /api/v1/app-content/identity`, cached for the splash and login before sign-in. `RemoteConfigService` (`lib/utils/remote_config_service.dart`) wraps Firebase Remote Config (`app_name`, `maintenance_mode`, `force_update_version`).
- The `MaterialApp.builder` stack in `main.dart` is, outside in: `AppDisplayScope` (display & reading, D-072) → `Directionality` → `AppKeyboardSupport` → `AppAssistantHost` → `LiveRoomLayer` around the Navigator; anything that must sit above every page goes there.

**Localization** — Strings live in `assets/translation.json` as `{ "key": { "en": "...", "ar": "..." } }`. Use `translate('key')` or `'key'.tr`; a missing key falls back to the key itself. Add both `en` and `ar` for every new key. Current language is `AppConfig.lang` (switched by `LangProvider`); use `pageDirection` for RTL/LTR.

**Offline** — Downloads are phone / desktop only: every entry point checks `kDownloadsAvailable` and links naming the page go through `linkAvailableHere` / `isDownloadsLink` (`lib/core/offline/downloads_availability.dart`); on the web `/downloads` redirects home. `lib/core/offline/` holds connectivity (one app-wide online/offline answer, wired into `topRouteObserver`) and encrypted offline video downloads (AES-CTR via pointycastle). Offline attendance can relay through a nearby online classmate (`features/shared/attendance/`: `nearby_connections` between Android phones, plus a Bluetooth LE GATT transport in `relay_ble_transport.dart` for iPhones and Android ↔ iPhone — that file was written without checking the package source; see its header).

**Course video player (`lib/features/shared/session/video/`)** — `VideoPlayerScreen(material, playlist:)` is the one player for every caller; switching lectures happens in place, never by pushing a second screen; pure parts live in `vod_player_parts.dart`. Details: `docs/guides/video-player.md`.

**Live (rooms, media, sharing and drawing, lobby, share links, meeting recordings, points / live plan)** — `lib/features/teacher/sessions/live/` (the room) and `lib/features/shared/live/` (rooms, lobby, recordings); each folder's CLAUDE.md holds the details, working notes in `docs/live/` (`NOTES.md` first). Rules that bite elsewhere: the room is not a route — `PreJoinPage` opens it through `LiveRoomHost.open` into `LiveRoomLayer` (D-059); draw every track with `LiveVideoView`, never livekit's `VideoTrackRenderer`; `RoomPage(isGuest: true)` must never call an authenticated API (a 401 redirects to login); every server, media and LiveKit URL is https / wss.

**Native code** — screen recording and screen sharing use platform channels (`com.example.flutter_education_app/native_recorder`, `/radios`); recordings upload in chunks. The Android / iOS sides: `docs/guides/native.md`.

**Organizations, governance, timetables, registrar (`lib/features/org/`)** — the details are in `lib/features/org/CLAUDE.md`; the backend is next door at `../back` (`routers/organization/`, `services/organization/`): check payloads there, don't trust the notes alone. Rules that bite elsewhere too: several org PUTs replace the whole object (join policy, schedule, room, program, academic settings), so always send every field; the server stores naive UTC (send `orgUtc()`, read `orgParseUtc()`); a new server error code gets a text in `orgErrorText`; org screens use `t(ar, en)` from `admin_common.dart`; every non-student org role opens `org_dashboard_screen.dart` (D-103), students `org_member_dashboard.dart`; `AppModeController.instance` holds the Organization / Individual mode and `leaveToPersonal` / `ContextExitButton` leave it (every org screen needs a way out). Backend changes follow `../back/CLAUDE.md`: e2e tests under `tests/org_v2/` (Python 3.12, `PYTHONUTF8=1`, a per-run SQLite `DATABASE_URL` without a local Postgres), every org API contract change in `../back/FLUTTER_API_CHANGES.md`, a schema change is the model change AND a new Alembic revision.

**Organization dashboard (D-103)** — every org page wears `OrgPageHeader` (title · ONE primary action · Search · Refresh with "Updated …" · calendar · bell · switcher; the shell's top bar is off), `OrgPushedPage` when pushed on top, and only when `orgUsesDashboardHeader(context, orgId)` on a screen a student or a deep link may also open; a page with its own loader calls `OrgPageRefresh.register(context, _reload)` / `reportUpdated`; the body is `org_page_kit.dart` (`OrgPageBody`: one primary action, at most one search and one filter, cards, never wide tables on phones). Home = Needs your attention (`GET /orgs/{id}/tasks`, one-tap `POST …/tasks/{task_id}/{action}`, audited `meta.via = "quick_actions"`) · My departments (the server's `tabs` with levels) · Insights (`GET /orgs/{id}/insights`, aggregates only, lazy and fetched in parallel, kill switch `org.insights`); the command palette is Ctrl+K (`AppCommandPaletteScope`, `GET /orgs/{id}/search`, kill switch `org.search`); `org_access_changed` or a 403 `student_forbidden` / `org_forbidden` reloads `/mine?members=1`. Details and tests: `docs/guides/org-dashboard.md`.

**Calendar and meetings (`lib/features/shared/calendar/`)** — ONE schedule page, `SchedulePage` (D-085), fed by ONE `GET /me/calendar` per visible range through `CalendarStore`. Creating or moving a meeting answers 409 `attendees_busy` unless sent with `force`; a failed weekly-appointments load must never fail the page. Details: `docs/guides/calendar.md`.

**Web** — Code that is not web-safe sits behind `kIsWeb` checks or conditional-import stubs (`url_strategy_stub.dart` / `url_strategy_web.dart`, `web_notification_web.dart` using `package:web`). Do not import `dart:io`-only APIs from code that runs on web without such a guard.
