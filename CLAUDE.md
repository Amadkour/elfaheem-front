# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Flutter education platform (VOD courses, live sessions, attendance, organizations) — product name NextBrain by DoubleY, application id `com.doubley.nextbrain` on every platform (D-145), Dart package name `flutter_education_app` (internal, never renamed), Firebase project `nextbrain-2y` (the old `elfaheem` stays as the fallback for installed apps, D-145), backend at `AppConfig.baseUrl` (`https://nextbrain.site/api` unless built with `--dart-define=API_BASE_URL=…`; a release build accepts only an `https://` override, see `resolveApiBaseUrl`). Targets Android, iOS and Web. The web app is served by nginx under **`/app/`** (every web build uses `--base-href /app/`; the start-URL parsers strip it, `lib/utils/web_base_path.dart`); the site root is the static landing in `landing/` (Astro, its own README), and old root URLs are redirected to `/app/…` (D-270). Default UI language is Arabic (RTL); English is also supported.

App versions: `codemagic.yaml` holds every build workflow (D-144). `tools/runner/` runs the SAME workflows on the owner's computer for free (D-146, the default "Build on: My computer"), so keep website workflows free of Codemagic-only tools; store uploads stay on Codemagic. `scripts/release/` is the direct-download publisher (D-137).

CI (`.github/workflows/ci.yml`, Flutter 3.47.7 stable) runs on pushes to `production`, `main` and `feature/**` and on every pull request — a push to any other branch (e.g. `organizations`) runs nothing until a PR is opened. It gates on: 0 analyzer warnings/errors (plain `flutter analyze` exits 1 on info lints, which are allowed — use the flags above, or count `" warning - "` / `" error - "` lines), the test suites above, `flutter build web --release`, and gitleaks over the tree and the new commits (`.gitleaks.toml`: an allowlist entry must match rule AND path AND value, with a reason).

**Test harnesses** (how each works, what to regenerate: `docs/guides/testing.md`):
- `test/contract/` checks every path handed to `ApiClient` against the backend's route snapshot `api_paths.json`, the kill-switch keys against `feature_keys.json`, and the hand-written parsers against REAL server payloads in `test/fixtures/payloads/` and `test/fixtures/points/`. After a server route or kill-switch change, regenerate from `../back`: `.venv312/Scripts/python scripts/contract/export_api_paths.py --front ../nextbrain-front` (or `py -3.12`; plain `python` is not on PATH); after a payload change, `../back/tests/contract/dump_payloads.py`. A deliberate gap goes in `knownMissing` / `notInCatalog` with a reason, and an entry no longer needed fails the test too.
- `test/perf/home_requests_*_test.dart` pump each role's real home over `FakeApi` (`test/support/fake_api.dart`) and fail above `homeBudgets`; a change that makes a home cheaper lowers its budget in the same commit. `test/ui/a11y_guidelines_test.dart` checks targets, labels and contrast; a failure that can't be fixed yet goes in its `_blocked` list with a reason.
- New widgets go through `expectNoLayoutErrors` (`test/ui/layout_harness.dart`: 320×640 and 1400×900, ar/en, `textScaler` 1.3): "no overflow on any screen size" is a project requirement. A widget that needs a platform object (LiveKit `Room`, `VideoPlayerController`) gets a plain-values presentational widget next to it, and that is what the harness tests.
- `test/visual/` (tag `visual`, NOT a CI suite): `flutter test test/visual --update-goldens [--plain-name student]` renders every home for review by eye. `EXPORT_SAMPLES=<dir> flutter test test/org/org_export_test.dart` writes sample xlsx / docx / pdf to open in Office.
- Dart test gotchas: a record that holds a list never equals another (`expect((a.list, b), …)` fails), so expect the list on its own; the wildcard pattern is `(_, _)`, not `(_, __)` (lint); `AppConfig.lang` is set in `setUp` and flipped inside a test to check both languages.

`flutter_webrtc` is overridden to a fork (`github.com/Amadkour/flutter-webrtc`) in `dependency_overrides`, pinned to a commit `ref:` (change it on purpose, D-010); `screen_protector` is pinned to 1.5.1 on purpose (see the pubspec comment), and only `lib/core/screen_security.dart` imports it: protected screens (video player, exams) call `ScreenSecurity.protect(owner)` / `release(owner)` (D-083), never the plugin, so one screen's dispose can't drop another's protection and a screen share keeps protected areas black. Don't add the `excel` package: it forces `archive` 3.x, which downgrades `image` and `flutter_launcher_icons`. That's why every Excel/Word file is written by hand on top of `archive` 4. When adding a package, check that `pubspec.lock` gains only that package and nothing gets downgraded.

The code is not `dart format`-ed (formatting `lib/features/org` would rewrite every file). Don't run `dart format` on files you edit: it buries the real change in thousands of lines of re-wrapping. New files are written formatted by hand (D-003).

Docs: `D-nnn` references point to `docs/DECISIONS.md` (design decisions and deliberate deviations; add one when you deviate). `docs/ARCHITECTURE.md` is the long-form architecture. Multi-session jobs each keep their own tracker: on a resume, read the one for the job you are on and continue its first task not `done`/`verified` — the root `PROGRESS.md` is the platform-polish job (`feature/platform-polish`, per-track analyses in `docs/polish/`); live work (LiveKit room, recording, performance) resumes from `docs/live/NEXT_SESSION.md`, whose §1 is the next task (`docs/live/PROGRESS.md` is its tracker, `docs/live/NOTES.md` its notes). `docs/PROGRESS.md` is the older phase log of the RBAC/exams/RAG refactor (history), `TIMETABLE_NOTES.md` the running notes of the timetable rebuild, `docs/AUDIT.md` / `docs/SECURITY_SCAN.md` dated read-only audit reports (their backend halves are in `../back/docs/`), and `documents/` (gitignored: local only, absent from a fresh clone) holds developer guides and slides (Word + PowerPoint per topic, generated from both repositories by `documents/_build/build_*.py` on top of `_build/nbdoc.py`; rebuild them after a large change, see `documents/README.md`). ## Architecture

**Startup (`lib/main.dart`)** — `_bootstrap()` paints a boot splash immediately, runs `_initCore()` (storage, `assets/translation.json`, Firebase, Remote Config, connectivity, offline videos, …) with each step wrapped in `_safe(name, fn, seconds:)` timeouts so one slow service never blocks launch, then runs the real app. The splash is `lib/design/boot_splash.dart` (`BootSplash`, details in `docs/guides/boot-splash.md`). Only a storage failure shows `_FatalApp`. Routing is a single `onGenerateRoute: _router` switch over named routes; the initial route comes from `MyAuthProvider.homeRoute`, which maps the user role (`admin`/`super-admin`/`developer` → `/admin_dashboard`, `teacher`, `parent`, `org-admin`/`org-staff` → `/org_dashboard` (every non-student org role, even one who manages nothing, D-103); otherwise student `/dashboard`). An org-admin/org-staff who last left the organization for their personal account starts on `/dashboard` (remembered per user). Offline start-ups route to `/downloads` (or student dashboard + downloads on top).

**Features (`lib/features/<feature>/`, D-947)** — one folder per feature, not per role; a role's own screens sit in a `student/`, `teacher/` or `admin/` subfolder inside the feature. `home` (`home/student`, `home/teacher`: each role's home and dashboard), `courses` (lists, `course_space`, `course_profile`, `category`, `roadmap`), `sessions` (material, the video player, the teacher's sessions), `live` (rooms, lobby, recordings; `live/room` is the live room), `exams` (the Exam Engine; `identity`, `legacy`), `attendance`, `payments` (enrollment, subscription, points, enrollment requests), `certificates`, `data_lab`, `analytics`, `profile` (display, legal, passcode, public / study profile), `messaging` (chat, inbox, notification), `calendar`, `rag`, `records`, `help`, `exports`, `downloads`, `upload`, `guest`, `share`, `get_app`, `onboarding`; plus the role areas that stay whole: `admin`, `org`, `parent`, `auth`, and `ads` (`ads_pages.dart`: the home slider, the super admin's ads page with teacher-ad approval, and the teacher's own ads). Imports between features are `package:flutter_education_app/…`. The layout came from a scripted move (`tool/apply_moves.dart` over `tool/moves/M1..M10.tsv`); a branch still on the old layout runs `dart run tool/apply_moves.dart --fix-imports` after merging.

**Home screens and badges** — every role's home is built from `lib/design/home_kit.dart` and kept short and calm (D-102). Its data is ONE call, `GET /api/v1/me/home` (`MeHomeService.instance`); badge counts are ONE call, `GET /api/v1/me/attention` (`AttentionService.instance`), drawn with `AttentionBadge(tabKey: AttentionTabs.x, …)`; a new tab key goes in `AttentionTabs` AND the server's `TABS` (`../back/services/attention_service.py`). Layout, type weights, density rules, Go live, Live now: `docs/guides/home-screens.md`.

**Course lists, course page, course profile** — both roles' course lists draw ONE card, `CourseListCard`, and prices are always `coursePriceLabel`; `CourseSpace` is THE course page (plain values in slots, reads no provider) with ONE sessions timeline, `course_sessions.dart`; the course profile is one screen for every role. Details: `docs/guides/course-pages.md`.

**Course roadmap + recommendations (`lib/features/courses/roadmap/`, D-120)** — personal accounts on personal courses ONLY: an organization account or an organization course gets neither (server 403 `individual_only` / `org_course` / `feature_off`; `roadmapHiddenError` draws nothing). For a personal course the course form never sends `next_course_ids` (it would undo the Path tab), and the student home's journey card comes from `/me/home` with no request of its own. The Path tab, the teacher's editor, "Recommended for you", the super admin's weights page, kill switches and tests: `docs/guides/roadmap.md`.

**Real-time (`lib/core/live/`, Track D)** — `LiveEventsClient.instance` holds ONE Server-Sent Events stream, `GET /api/v1/me/events`, and feeds it into `LiveEvents.instance`, the same bus the silent FCM pushes use, deduplicated by event id. The stream is open only while signed in, in front and something has called `bind()`. It reconnects with backoff and `Last-Event-ID`, and a 401 retries once through `POST /me/events/ticket`. A screen that waits on a job or watches a list must not poll on a timer: use `EventOrPoll` (timer style) or `JobWatch` (`await`-loop style) from `event_wait.dart`, which run on the event and keep a slow poll only as the fallback. Tests: `test/org/live_events_client_test.dart`, `event_wait_test.dart`, and `live_events_soak_test.dart` (soak; the real-server run is opt-in).

**Navigation glue (`lib/utils/widget/`)** — `AppNavigator` (`app_navigator.dart`) is the one place that opens a "module" from a notification tap, a push, a dialog button or a shared link, always through `navigatorKey` from `main.dart`; add new deep-link targets there rather than in each caller. `DeepLinkService` (`deep_link_service.dart`) handles course share links `https://nextbrain.site/c/<courseId>?ref=<sharerUserId>`, which Flutter's default deep linking feeds to `onGenerateRoute` as `/c/<id>?ref=<uid>`. `VersionCheckService` (`lib/core/version_check_service.dart`) runs once at startup against `GET /app/version-check` and shows a blocking (`must_update`) or dismissible (`should_update`) dialog. The rest of `lib/utils/widget/` is the older widget set (`BasePage`, `ParentComponent`, `PrimaryButton`, `AppBar`, text fields, …) that existing screens still use; new UI comes from `lib/design/` (below), which wraps and re-exports what it needs from there.

**State** — `provider` package. All app-wide `ChangeNotifier`s are registered in `lib/core/providers.dart` (`appProviders`); add new global providers there. Feature providers extend `BaseProvider` (`lib/core/base_provider.dart`) and wrap API calls in `run(() => ...)`, which manages `ProviderState` (idle/loading/success/error), sets `errorMessage`, and does one outer retry. Some app-wide state uses singletons (`XService.instance`, `ViewAsState.instance`, `AppConnectivity.instance`).

**Networking (`lib/core/api_client.dart`)** — `ApiClient` (`ApiClient()` returns `ApiClient.instance`) is a singleton on Dio with `get/post/put/patch/delete/postForm/postMultipart`, and every method takes an optional `headers:`. It throws only `ApiException`: in UI show `ApiException.from(e).message` (`code` holds server codes such as `DEVICE_MISMATCH`; coded errors outside org screens get bilingual text from `apiErrorText` in `lib/core/api_error_text.dart`). On every request it:
- refreshes tokens on 401 with rotation (`lib/core/token_storage.dart`: an old refresh token is dead after one use);
- encrypts the body (envelope `{"n","ct"}`) and, on mobile, pins the server's PUBLIC KEY (`lib/core/cert_pin.dart`, D-946: the server renews with `certbot renew --reuse-key`; a key change needs a new app build first, and a refused pin on our host reads "please update the app"). Every client that talks to the API host, the encryption handshake's included, comes from `_pinnedHttpClient()`;
- adds the device-ID, `X-View-As` and teacher-onboarding headers.

Debug request logs go through `redactForLog`: add any new secret field to `logSensitiveKeys`. The headers in detail, the MFA redirect and `server_busy`: `docs/guides/networking.md`; MFA and fingerprint / Face ID sign-in: `docs/guides/auth-biometric.md`. Cleartext is refused on devices except `127.0.0.1` / `localhost` (offline-video loopback) and `10.0.2.2` (emulator → local stack, D-010): every server, media and LiveKit URL must be https / wss.

**Exam Engine, RAG and the app assistant** — separate backend services (`../back/exam_engine`, `../back/rag_service`) reached through the same `ApiClient` under `/api/v1/exam/…` and `/api/v1/rag/…`; the details are in `lib/features/exams/CLAUDE.md` (engine calls, exam taking, quick exam, generated questions, printable papers, scanned sheets, offline sittings) and `lib/features/rag/CLAUDE.md` (the floating app assistant, the model pipeline, the Super Admin's console, the features guide). Paper exams with bubble sheets (D-150 – D-160, the decisions are in `../back/docs/DECISIONS.md`) — the setup wizard, scanner, sheet types, review and results in `lib/features/exams/paper/` (`exam_setup*`, `scan/`, `templates/`, `review/`), the student's identifier dialog in `lib/features/exams/identity/`, end to end in `docs/guides/paper-exams-omr.md`. The super admin's AI Models page and the floating model-download bar are `lib/features/admin/models/` over `lib/core/models_hub/` (the model hub's API at `/api/v1/models/…` + `ModelDownloads.instance`; `ModelDownloadsHost` sits in the `MaterialApp.builder` stack), kill switch `models.admin`. Rules for every feature: **when you add a user-facing feature, add it to `../back/data/app_features_guide.json`** (group, roles, Arabic + English name, summary, place, steps, the kill-switch keys that hide it — D-052), and **a new kill-switch key** goes into `../back/services/feature_catalog.py`, then regenerate the snapshots (same command as the API contract test): `test/contract/feature_keys_test.dart` fails on a key the catalog lacks, because a super admin could never switch it off.

**Server-driven theme & feature flags** — `ThemeConfigProvider` (`lib/config/theme/`) loads the theme from `GET /api/v1/theme/{platform}` and builds `materialTheme()`. Always read colors via `context.colors`, never hard-coded colors. The same response sets `AppConfig.disableList` (feature kill-switch ids, e.g. `profile.logout`, `teacher_tab_analysis`). To make UI switchable, wrap it in `ParentComponent(featureKey: '...')` (hides it), or give a `BasePage` a `ValueKey('<id>')` (shows a "coming soon" page). `AppConfig.setDisableList` rebuilds the whole widget tree when the list changes.

The disable list has layers. The effective list combines:
- the platform list from the theme response;
- the open organization's list (`AppConfig.setOrgDisableList`);
- `AppConfig.orgEntryKeys`, while the super admin has organizations switched off (`AppConfig.orgsEnabled` / `setOrgsEnabled`, from `orgs_enabled` in the theme response).

A super-admin OFF always wins, because an organization can only add keys. Hidden features disappear rather than greying out. With organizations off, the server answers 403 `orgs_disabled` on org routes, and `/org_dashboard` is wrapped in `OrgsGate`. The theme response's `platform_settings` also sets the platform timezone and 12h/24h (`AppTime.configurePlatform`).

**UI kit** — the design system (D-180) with examples and a new-screen checklist is `lib/design/README.md`; every rule below with its full reasoning is in `docs/guides/ui-kit.md`. New screens use `lib/design/app_kit.dart` (`AppHero`, `AppCard`, `AppEmpty`, `AppListSkeleton` rather than spinners, `AppField`, `showAppSheet`, `appConfirm`, …; the usage table is that file's header comment) inside `BasePage` (`lib/utils/widget/base_page.dart`: the canvas — a tint of the sidebar colour under a faint lattice, `AppCanvas`, D-949 — and the kill switch; the upload-progress footer is drawn once for the app by `UploadQueueHost`). Never:
- a raw number for spacing, radius, motion, touch size, shadow or type role: tokens from `lib/design/app_tokens.dart` (D-103). Never a pixel `maxWidth` either: the page names a width role, `AppWidth.form` / `reading` / `content` / `wide` / `full` (D-304);
- `Switch` / `SwitchListTile` (use `AppSwitch` / `AppSwitchTile`), any dropdown but `AppDropdown`, or a chart package (`lib/design/app_charts.dart`, D-063);
- a hard-coded color: use `context.colors`, and on heroes / sidebars the on-hero roles (`c.onHero`, `heroGlass`, …), never `Colors.white` / `Colors.black`;
- a font family name in a TextStyle, or a `static final` / `const` TextStyle (either one freezes the person's font choice): use `appText(...)`, the theme's styles or `AppFonts.family` (D-072);
- an icon picked by language: `arrow_back/forward`, `chevron_*`, `navigate_*`, `send` and `open_in_new` mirror by themselves; `logout`, `login`, `exit_to_app`, `north_east`, … go through `DirIcons`; `CupertinoIcons.back` / `forward`, not `chevron_back` / `chevron_forward` (`test/ui/rtl_icons_test.dart` checks);
- a time or date that is not formatted by `AppTime` (`lib/core/app_time.dart`: platform / org timezone, 12h/24h);
- a hand-rolled table export: use `showAppExportSheet` inside `bilingualExport(() => …)` (the Export Studio, `docs/guides/export-studio.md`);
- a shell-level `AttentionService` listener: every dashboard is `AppShell` over `DashboardItem`s (D-062) with counts drawn by `ShellBadge` at the leaf. Tabs are lazy (`LazyTabStack`, D-077), so a tab must not assume it loaded at app open;
- a decorative loop (shimmer, pulse, shine) without `syncMotionLoop(context, controller)`, which parks it under Reduce motion (`docs/guides/display-settings.md`).

Settings / More pages are `AppSettingsPage` (`app_settings.dart`). Keyboard handling (Enter → next field / primary button, Esc, Ctrl+K) is global through `AppKeyboardSupport`; override it with `EnterSubmits` (`docs/guides/keyboard.md`).

**Cross-cutting helpers (easy to miss, use them instead of rolling your own)** —
- `showAppNotice(text, error:)` (`lib/design/app_notice.dart`) for every toast: it is drawn in the root Navigator's overlay, so it stays visible above sheets and dialogs where a `SnackBar` is hidden. New code uses it rather than `ScaffoldMessenger` / `SnackBar` (a few older screens still do).
- `AppEmailField` / `AppPasswordField` / `AppPhoneField` / `AppUrlField` (`app_inputs.dart`) are the identity inputs with validation and bilingual messages; login and forgot-password keep their single identifier field on purpose.
- `AppHScroll` (`app_hscroll.dart`) wraps wide tables / grids so they scroll with a mouse on web and desktop; `AppScrollBehavior` is set on `MaterialApp.scrollBehavior` already.
- `HelpInfoButton(pageId:)` (`lib/features/help/`) is the "i" of every page: pass `helpPageId: '<D-170 id | home.<role>/<tab>>'` to `ScreenAppBar` / `OrgPageHeader` / `OrgPushedPage` / `HomeHeader` (or `helpEntryForMenu` where a header has no room, e.g. the live room's More menu); the text is server-managed (`GET /help/pages/{id}`, admin page `admin.help`, kill switch `help.info`) and `test/ui/help_ids_test.dart` checks every wired id exists.
- `showAppImageCropper(context, bytes, shape:)` (`app_image_cropper.dart`) is the one cropper (avatars, covers, logos), pure Flutter, works on web.
- `LiveEvents.instance` (`lib/utils/live_events.dart`) is the in-app event bus: `NotificationService` (`features/messaging/notification/notification_service.dart`, FCM + local notifications, the top-level background handler) turns a silent push into a `LiveEvent`, as does the SSE stream above, and screens subscribe with `listen({LiveEvents.complaints}, …)`. Event names must match `../back/services/live_update_service.py`. A visible push tap goes through `AppNavigator`.
- `topRouteObserver` (`lib/utils/top_route_observer.dart`) is the single `NavigatorObserver` (installed once in `main.dart`): every push / pop tells `AttentionService` to refresh, and its connectivity listener emits `LiveEvents.connectivity`, kicks the offline attendance / exam syncs on reconnect and keeps the downloads shortcut — hook route- or reconnect-dependent work there, not in individual screens.
- `AppIdentity.instance` (`lib/core/app_identity.dart`) is the admin-set name / tagline / logo from the public `GET /api/v1/app-content/identity`, cached for the splash and login before sign-in. `RemoteConfigService` (`lib/utils/remote_config_service.dart`) wraps Firebase Remote Config (`app_name`, `maintenance_mode`, `force_update_version`).
- The `MaterialApp.builder` stack in `main.dart` is, outside in: `AppDisplayScope` (display & reading, D-072) → `Directionality` → `AppKeyboardSupport` → `AppAssistantHost` → `LiveRoomLayer` → `UploadQueueHost` (the ONE upload footer, D-949) around the Navigator; anything that must sit above every page goes there.

**Localization** — Strings live in `assets/translation.json` as `{ "key": { "en": "...", "ar": "..." } }`. Use `translate('key')` or `'key'.tr`; a missing key falls back to the key itself. Add both `en` and `ar` for every new key. Current language is `AppConfig.lang` (switched by `LangProvider`); use `pageDirection` for RTL/LTR. A count with a noun goes through `countText(n, ar1:, ar2:, arFew:, arMany:, en1:, en:)` (`lib/core/plural.dart`, Arabic's 1 / 2 / 3–10 / 11+ forms), not `'$n ${...}'`. The `MaterialApp` locale follows `AppConfig.lang` (`lib/core/app_locale.dart`) so screen readers and Material's own labels match the app language; digits stay Latin.

**Offline** — Downloads are phone / desktop only: every entry point checks `kDownloadsAvailable` and links naming the page go through `linkAvailableHere` / `isDownloadsLink` (`lib/core/offline/downloads_availability.dart`); on the web `/downloads` redirects home. `lib/core/offline/` holds connectivity (one app-wide online/offline answer, wired into `topRouteObserver`) and encrypted offline video downloads (AES-CTR via pointycastle). Offline attendance can relay through a nearby online classmate (`features/attendance/`: `nearby_connections` between Android phones, plus a Bluetooth LE GATT transport in `relay_ble_transport.dart` for iPhones and Android ↔ iPhone — that file was written without checking the package source; see its header).

**Course video player (`lib/features/sessions/video/`)** — `VideoPlayerScreen(material, playlist:)` is the one player for every caller; switching lectures happens in place, never by pushing a second screen; pure parts live in `vod_player_parts.dart`. Details: `docs/guides/video-player.md`.

**Live (rooms, media, sharing and drawing, lobby, share links, meeting recordings, points / live plan)** — `lib/features/live/room/` (the room) and `lib/features/live/` (rooms, lobby, recordings); each folder's CLAUDE.md holds the details, working notes in `docs/live/` (`NOTES.md` first). Rules that bite elsewhere: the room is not a route — `PreJoinPage` opens it through `LiveRoomHost.open` into `LiveRoomLayer` (D-059); draw every track with `LiveVideoView`, never livekit's `VideoTrackRenderer`; `RoomPage(isGuest: true)` must never call an authenticated API (a 401 redirects to login); every server, media and LiveKit URL is https / wss.

**Native code** — screen recording and screen sharing use platform channels (`com.doubley.nextbrain/native_recorder`, `/radios`, …; identical on both sides); recordings upload in chunks. The Android / iOS sides: `docs/guides/native.md`.

**Organizations, governance, timetables, registrar (`lib/features/org/`)** — the details are in `lib/features/org/CLAUDE.md`; the backend is next door at `../back` (`routers/organization/`, `services/organization/`): check payloads there, don't trust the notes alone. Rules that bite elsewhere too: several org PUTs replace the whole object (join policy, schedule, room, program, academic settings), so always send every field; the server stores naive UTC (send `orgUtc()`, read `orgParseUtc()`); a new server error code gets a text in `orgErrorText`; org screens use `t(ar, en)` from `admin_common.dart`; every non-student org role opens `org_dashboard_screen.dart` (D-103), students `org_member_dashboard.dart`; `AppModeController.instance` holds the Organization / Individual mode and `leaveToPersonal` / `ContextExitButton` leave it (every org screen needs a way out). Backend changes follow `../back/CLAUDE.md`: e2e tests under `tests/org_v2/` (Python 3.12, `PYTHONUTF8=1`, a per-run SQLite `DATABASE_URL` without a local Postgres), every org API contract change in `../back/FLUTTER_API_CHANGES.md`, a schema change is the model change AND a new Alembic revision.

**Organization dashboard (D-103)** — every org page wears `OrgPageHeader`, `OrgPushedPage` when pushed on top, and its body is `org_page_kit.dart` (`OrgPageBody`: one primary action, at most one search and one filter, cards, never wide tables on phones). Home, quick actions, insights, the Ctrl+K palette, kill switches and the reload on an access change: `docs/guides/org-dashboard.md`.

**Calendar and meetings (`lib/features/calendar/`)** — ONE schedule page, `SchedulePage` (D-085), fed by ONE `GET /me/calendar` per visible range through `CalendarStore`. Creating or moving a meeting answers 409 `attendees_busy` unless sent with `force`; a failed weekly-appointments load must never fail the page. Details: `docs/guides/calendar.md`.

**Web** — Code that is not web-safe sits behind `kIsWeb` checks or conditional-import stubs (`url_strategy_stub.dart` / `url_strategy_web.dart`, `web_notification_web.dart` using `package:web`). Do not import `dart:io`-only APIs from code that runs on web without such a guard.
